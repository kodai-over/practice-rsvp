# 改善要望のまとめと対応

Practice RSVP のメンバーがアプリの「要望」から送った改善要望を、**まとめる → 改善案を提案する → 管理者が承認したものだけ実装する → 改善済みにする** の順で扱う。
承認なしに実装・デプロイ・シートの書き換えをしない。

## 要望の置き場所

- スプレッドシート「Practice RSVP」の **「要望」シート**（アプリの「設定」→「要望を見る・送る」と同じデータ）
- スプレッドシートIDは `apps/gas/.clasp.json` の `parentId`（git には入っていないローカルファイル）
- 列: `要望ID` / `投稿者`（LINEユーザーID） / `投稿者名` / `内容` / `状態` / `管理者コメント` / `投稿日時`
- 状態は `未対応` / `検討中` / `改善済み` / `見送り` のいずれか（`packages/shared/src/types.ts` の `FEEDBACK_STATUSES`）
- **管理者コメントはアプリでメンバー全員に表示される**。書く文面は丁寧に、個人を責める内容や内部事情は書かない

## 手順

### 1. 要望を集める
1. `apps/gas/.clasp.json` を読んでスプレッドシートIDを得る
2. Google Sheets のツール（`get_values`）で `要望!A1:G` を読む。ツールが使えなければ、ユーザーにシートの内容を貼ってもらう
3. 状態が `未対応` と `検討中` のものを対象にする（`改善済み`・`見送り` は参考として件数だけ数える）

### 2. まとめる
- 同じ趣旨の要望を1つのテーマにまとめる（例:「通知がほしい」系、「画面が見づらい」系）
- テーマごとに種類を付ける: 不具合 / 使い勝手の改善 / 新機能
- コードと仕様を確認し、すでにできること・設定で解決できることは「案内で解決」とする
- 次の制約に反する案は出さないか、反する点を明記する
  - LINE公式アカウントの無料プランは月200通。グループへのプッシュ通知を増やす案は通数の見積もりを付ける
  - Gemini API は無料枠（請求先アカウントにつながない）
  - 操作は「スクショを送ってボタンを押すだけ」「ボタン1回」を最優先にする

### 3. 改善案を提案する（ここで一度止まる）
テーマごとに次の表で示す。

| # | 対象の要望（要望ID・投稿者名） | 要望の要約 | 改善案 | 変更する場所 | 規模（小/中/大） | 注意点（通知数・費用など） |
| --- | --- | --- | --- | --- | --- | --- |

そのあと AskUserQuestion（複数選択）で **どの案を実装するか** を管理者に選んでもらう。見送る案があれば理由も確認する。
承認が出るまで実装しない。

### 4. 承認された案を実装する
- 承認された要望の状態を、着手時に `検討中` にしてよいか確認してから更新する
- このリポジトリの作法に従う
  - 業務ロジックは `apps/gas/src/app/`（GAS非依存）に書き、`apps/gas/test/` にテストを足す
  - 画面は `apps/liff/src/`。`npm run dev:mock -w @pb/liff` で、スマホ幅で確認する
  - 共通の型・ルールは `packages/shared/src/`
- `npm test` と `npm run typecheck`、`npm run build -w @pb/gas`、`npm run build -w @pb/liff` が通ることを確かめる
- コミットは git-workflow スキルの規約に従う
- **デプロイ（`npm run deploy -w @pb/gas` と `git push`）は管理者の了解を得てから行う**

### 5. 改善済みにする
実装（とデプロイ）が終わったら、対応した要望ごとに次を書く文面を管理者に見せ、了解を得てからシートを更新する（`update_values`）。

- `状態`: `改善済み`
- `管理者コメント`: `改善済み（YYYY-MM-DD）: <何をどう変えたか。利用者向けの言葉で1〜2文>`
  - 例: `改善済み（2026-11-02）: 練習の前日に、アプリの「自分が行く」タブに印が付くようにしました。`

見送った要望は、管理者が了解した場合だけ `状態: 見送り`・`管理者コメント: 見送り（YYYY-MM-DD）: <理由>` にする。

### 6. 報告する
- 対応した要望（要望ID・テーマ・変えたこと）
- 見送った要望と理由
- 未対応のまま残した要望
- デプロイしたかどうか（していなければその旨）
